# 小鱼来了 · AI 信息发布平台

> 让每一条好项目，都被对的人看见

面向中国企业间**项目对接、投融资、EPC/EMC 工程、贸易采供、活动运营**的 AI 信息发布平台。
发布者输入文字或导入 PPT / PDF / Word / Excel / CAD / 图片 / 视频 / 压缩包，
AI 自动生成主标题、副标题、挑选主图，并对项目做**可靠性解析与风险提示**；
信息按**行业 + 城市**分发，支持**微信 / 朋友圈分享**、**留言 AI 自动回复**、
**关注推送**、**项目群聊**与**线上会议（含 AI 实时记录与纪要）**。

- **零外部依赖**：只用 Node.js 内置模块，不需要 `npm install`，没有构建步骤
- **一套代码同时适配手机与 PC**：移动优先响应式，微信内可直接打开
- **开箱即跑**：不配置任何密钥也能完整演示；配了 AI / 微信 / SMTP 就自动切到真实通道

## 一分钟启动

```bash
# 需要 Node.js 18+（推荐 20+）
node server.js
```

启动后终端会打印访问地址：

```
本机访问     http://127.0.0.1:8787
局域网/手机  http://192.168.x.x:8787     ← 手机连同一 WiFi 直接打开
```

首次启动会自动写入演示数据（4 位用户 / 16 条信息 / 10 个项目案例），
打开首页即可看到完整效果。

## 功能地图

### 一、三大板块：项目 / 活动 / 贸易

每个板块一个独立入口，各有一套字段与流程。

| 板块 | 覆盖类型 |
|---|---|
| **项目** | 投资（股权投资 / 产业投资 / 财务投资 / 并购 / 战略投资）、融资、EPC、EMC、转让、融资租赁、采购、招投标、委托加工、合作开发、技术合作、招商加盟 |

`EPC` = 工程总承包，`EMC` = 合同能源管理，均在类型说明里给出中文全称。

### 三、发布流程

```
输入文字 / 导入文件  →  AI 生成主标题 + 副标题 + 关键词  →  AI 可靠性解析
                     →  补齐要素（金额、地点、周期、联系方式…）  →  选择有效期  →  发布
```

- **导入文件**：图片、PPT、PDF、Word、Excel、CAD（DXF/DWG）、压缩包、视频、音频、文本。
  服务端会真正解析文档内容（不是只存文件）：docx 段落、pptx 逐页、xlsx 单元格、
  PDF 文本流、DXF 图层与实体统计、图片尺寸、MP4 时长……这些内容会一起喂给 AI。
- **AI 生成**：主标题（≤30 字，含地区/行业/动作/合作方式）+ 副标题（金额 · 规模 · 地点 · 方式）
  + 5 个备选标题 + 关键词，全部可手动修改。
- **AI 可靠性解析**：0–100 分 + 等级 + 「可信之处 / 风险提示 / 建议补充」三组结论。
  内置风控词表能识别「保本高回报」「资金盘」「虚拟币」「前置费用」等高风险话术并显著降分。
- **有效期**：7 / 15 / 30 / 90 / 180 / 365 天；到期自动下架，到期前 3 天自动提醒发布方。

### 四、留言 + AI 自动回复

- 支持多级回复、附件上传、@发布方。
- 留言后 **AI 会结合项目正文、附件内容、AI 解析结论与历史留言**自动回复，
  典型问题（联系方式、价格、资质要求、截止时间、报名方式、承接条件、资料索取）都能答；
  资料里没有的信息会明确说「发布方未公开，建议发起项目对接」，**不编造**。
- 发布方可以随时接管，或关闭 AI 自动回复。

### 五、关注与通知

- 可以关注：**信息**、**用户（发布方）**、**行业**、**城市**、**企业**。
- 被关注对象有新动态时，通过 **SSE 实时推送** + 站内未读红点 + 邮件摘要通知。
- 通知中心记录全部消息（关注动态、留言回复、AI 回复、群聊、会议邀请、纪要确认、项目进度、资质审核）。

### 六、项目对接与 14 步流程

点击「项目对接」会自动**建项目群 + 让双方成为项目成员 + 推进流程**，之后按 14 步走：

1. 发布项目（文字或导入文件）
2. AI 生成主标题与副标题
3. AI 分析项目可靠性及问题
4. 留言与回复
5. 新增后续（文字 + 导入文件）
6. 项目对接
7. 导入资质
8. 发布方确认项目是否匹配
9. 建立项目聊天群与会议，AI 实时记录与录音，生成双方后续跟进内容并发送确认
10. 确认是否线下会面，上传邀请函并确认
11. 上传初步协议及居间协议并确认
12. 线下会面，上传合作协议并确认
13. 上传合同并支付款项（居间费）
14. 项目结束

每一步都可写备注、传附件，全部留痕在项目详情页。

### 七、群聊 + 线上会议（仿腾讯会议）

#### 群聊

- **类型**：项目群 / 活动群 / 通讯录好友群 / 一对一
- **发消息**：文本、多文件（图片/PPT/PDF/Word/Excel/CAD/压缩包/视频）；SSE 实时到达；未读计数
- **邀请加入**：三种方式 ——
  - **邀请链接**：`…/#/chat/<群ID>`，微信内点开即进
  - **群二维码**：扫码入群（二维码由平台自己生成）
  - **群邀请卡**：Canvas 合成「群名 + 二维码 + 邀请文案」图片，可保存后发微信群/朋友圈
  - **搜索平台用户**：按昵称/企业名搜到人直接拉群
- **群公告**：群主发布，所有成员进群置顶可见，同时写入系统消息

#### 会议（对齐腾讯会议的常用交互）

**会议号 + 入会密码**

- 每个会议自动分配 **9 位会议号**（全局唯一，形如 `121670799`）+ **6 位入会密码**（可选）
- 任何人打开 `/#/join`，输入会议号即可加入；密码错误会被拒绝
- 顶部会议号一点即复制，方便口头告知

**邀请分享（3 种方式）**

| 方式 | 适用 |
|---|---|
| 邀请卡（图片 + 文字 + 二维码） | 发微信群、朋友圈；对方扫码直接进会 |
| 链接 + 会议号 | 直接转发链接，微信内自动展示标题与摘要 |
| 仅会议号 | 口头/短信告诉对方，他自己在小鱼来了输入会议号 |

**会前预览（Lobby）**

- 摄像头实时预览、麦克风电平条
- 一键开关摄像头/麦克风，改入会昵称
- 入会即静音 / 入会即关摄像头（主持人可配）

**会议中界面**

- **视频宫格**：1/2/4/9/16 人自适应布局；无人开视频时显示头像占位
- **底部控制栏**：静音 · 视频 · 共享屏幕 · 成员 · 聊天 · 举手 · 邀请 · 记录 · 录音 · 离开
- **成员列表**：实时显示在会/未入会、静音、举手状态
- **会议内聊天**：所有人可见，主持可关闭
- **举手**：参会人举手后，主持人成员列表立即看到 ✋
- **屏幕共享**：`getDisplayMedia`，多端 replaceTrack 热切换，停止后自动恢复摄像头
- **实时记录**：浏览器语音识别逐句转写并同步给所有参会人
- **录音**：MediaRecorder 录制后上传归档，会议页可回放
- **计时器 / 网络状态 / 录音中提示**

**主持人控制**

- 全体静音（向所有在线参会人推送 `force_mute`，客户端立即静音）
- 锁定会议（锁后新参会人无法加入，已在会的人可重连）
- 关闭会议聊天
- 移除成员（被移出者收到提示并被踢出）
- 结束会议（所有人收到通知并退出）
- 修改入会密码、切换入会即静音/关摄像头/允许未受邀者加入

**AI 纪要**

- 自动生成摘要、会议要点、已达成的共识、**双方后续跟进事项（含负责人与截止时间）**
- 发给双方确认；双方确认后自动归档到项目跟进记录

> 信令走 HTTP POST + SSE，**不需要 WebSocket 服务器**；
> 音视频是点对点 WebRTC，跨公网部署建议自建 TURN。

### 八、短视频与直播（首页轮播位）

首页大轮播不再是静态图，而是 **短视频 + 直播** 的混合信息流：

| | 短视频 | 直播 |
|---|---|---|
| 内容 | 上传 MP4 / MOV / WebM，复用文件服务 | 创建直播间，开播后推流 |
| 轮播表现 | 静音自动循环播放，右下角可一键开声音 | 封面 + 呼吸的 `● LIVE` 角标 + 观看数 |
| 进入 | 点整块跳到 `#/live/<id>` | 同上，进入直播间 |
| 数据 | 播放数、点赞数 | 观看数、点赞、实时聊天 |

**直播怎么实现的**

直播复用会议那一整套 WebRTC 信令，但拓扑不同：

- **普通会议**：网状（mesh），人人推流、人人互连
- **直播**：**星形**，主播推流给每个观众，**观众之间不互联**（只有主播发 offer）

这样开播即得：**9 位会议号、邀请链接与二维码、实时聊天、成员列表、AI 纪要**——
因为直播在数据上就是一个 `mode: 'live'` 的会议。

> ⚠️ 边界：星形拓扑下并发观众数受**主播上行带宽**限制，家用宽带大约 5–10 人。
> 要支持大规模直播需要引入 SFU / 转码服务器，那超出「零依赖单机」的范围，README 末尾的已知边界里有说明。

**发布入口**：首页底部导航中间的 **＋发布** → 选「直播」或「短视频」；
或直接访问 `#/feed/new`。列表页在 `#/feeds`。

### 九、分享到微信 / 朋友圈

## 外网访问

平台默认监听 `0.0.0.0`，局域网内手机可直接访问。要让公网访问，任选一种：

```powershell
# 方式一：内网穿透（最快，无需备案）
pwsh -File scripts/start-public.ps1 -Mode cloudflare-quick -SetBaseUrl

# 方式二：路由器端口映射，把 8787 映射到本机

# 方式三：部署到云服务器，用 Nginx 反代 + HTTPS（长期方案，见 deploy/README.md）
```

拿到公网地址后写入 `.env`，分享链接与二维码就会用这个地址：

```env
PUBLIC_BASE_URL=https://your-domain.com
```

### ⚠️ 不要用 ngrok 免费版

ngrok 免费版会对浏览器流量注入警告页（`ERR_NGROK_6024`），后果比想象中严重：

| 访问方式 | ngrok 免费版的返回 |
|---|---|
| 浏览器地址栏（`Accept: text/html`） | 约 2.9 KB 警告页，需点「Visit Site」 |
| **fetch / XHR 调接口** | **269 字节纯文本 → 所有 API 请求全挂** |
| **微信内置浏览器** | **纯文本，没有可点的按钮 → 死路** |

也就是说：即使访客在电脑上点过了「Visit Site」，应用里的每一次接口调用仍可能被拦；
而**微信里打开分享链接会直接看到阻断页**——这与「微信分享」这个核心需求根本不兼容。

**cloudflared 快速隧道没有这个问题**，所以脚本默认用它。

### 别忘了验证「用户实际看到的那一页」

这一点踩过坑：排查时如果用 `ngrok-skip-browser-warning` 这类跳过头去测试，
测到的恰恰是被官方**替换掉**的正常响应，站点看起来完全健康，
而真实访客拿到的是阻断页。所以本项目提供了专门的体检脚本：

```powershell
pwsh -File scripts/check-public.ps1
```

它会**不带任何跳过头**、分别用浏览器 UA、XHR 方式、微信 UA 各请求一遍，
并显式检测提示页，最后核对分享链接与二维码是否指向公网地址。

> 微信 JS-SDK 分享需要在公众号后台配置「JS 接口安全域名」，
> 该域名必须备案并支持 HTTPS。
>
> cloudflared 快速隧道的域名每次重启都会变化（无固定网址）。
> `start-all.ps1` 会自动把新域名同步进 `.env` 并重启服务，
> 但**要固定网址就必须有自己的域名**——把域名解析到云服务器上，见 `deploy/README.md`。

## 配置

复制 `.env.example` 为 `.env` 后按需修改，**全部留空也能跑**。

| 变量 | 作用 | 不配置时 |
|---|---|---|
| `AI_API_KEY` / `AI_BASE_URL` / `AI_MODEL` | 大模型（任何 OpenAI 兼容接口：DeepSeek / 通义 / Moonshot / GPT） | 使用内置本地规则引擎 |
| `WECHAT_APP_ID` / `WECHAT_APP_SECRET` | 公众号网页授权 + JS-SDK 分享 | 演示登录 |
| `WECHAT_OPEN_APP_ID` / `WECHAT_OPEN_APP_SECRET` | 开放平台扫码登录 | 隐藏扫码入口 |
| `SMTP_*` | 邮件验证码与通知 | 验证码直接返回并写 `data/outbox.log` |
| `SMS_PROVIDER` | 短信网关 | `demo`：验证码写控制台 |
| `PUBLIC_BASE_URL` | 分享链接/二维码的根地址 | 按访问者浏览器地址生成 |
| `MAX_UPLOAD_BYTES` | 上传上限 | 512MB（支持视频） |

**接大模型**（示例，DeepSeek）：

```env
AI_BASE_URL=https://api.deepseek.com/v1
AI_MODEL=deepseek-chat
AI_API_KEY=sk-xxxxxxxx
```

配好后，标题生成、项目解析、留言回复、会议纪要会自动切到大模型，
返回值里的 `source` 字段会从 `local` 变成 `ai`；调用失败会自动回退本地引擎，不会中断服务。

### 二维码是怎么被独立验证的

二维码是本项目唯一"自己从零实现"的编码算法，因此单独做了**不信任编码器任何表**的逆向验证：

1. **数模块**：从生成的矩阵里独立数出数据模块总数，与 ISO/IEC 18004 公布的总码字数
   （v1=26 … v10=346、v40=3706）逐版本比对 —— 验证容量与功能图形布局。
2. **格式信息**：用**另写一份** BCH(15,5) 实现重算，先用公布的 4 组 mask0 标准值锚定实现本身，
   再校验矩阵里真实写入的两份格式信息 —— 验证纠错等级编码与掩码号。
3. **版本信息**：同样用独立 BCH(18,6) 与公布值 `0x07C94` 比对。
4. **码字还原**：反掩码 → 蛇形读取 → 去交错，得到码字序列。
5. **RS 校验**：**穷举**分块结构（块数 × 每块纠错码字数），用独立实现的 GF(256)
   计算校验子，只有正确结构才会让所有块校验子全零 —— 在不查任何表的前提下同时验证了分块表和纠错码字。
6. **原文还原**：解析数据码字，还原出原始字符串并与输入逐字节比对。
7. **PNG 往返**：独立解码生成的 PNG，重建矩阵并再次完成 4–6 步。

覆盖 v2 → v25 共 8 组用例（含中文、长文本、H/Q/M/L 四档）。

> 说明：以上是**软件层面**能做到的最强验证。上线的二维码建议再用手机实扫一次
> `qr-smoke.png`（测试会生成）做最终确认。

## 已知边界

- **持久化用 JSON 文件**（每个集合一个文件，内存索引 + 原子写入）。
  十万级数据量下没问题；再往上建议把 `src/store/db.js` 的 `Collection`
  换成 SQLite / PostgreSQL —— 调用方只依赖 `insert/find/update/remove` 这几个方法。
- **微信通讯录无法直接读取**：微信没有开放通讯录接口。平台提供三种替代方案
  （系统通讯录导入、粘贴导入、vCard/CSV 上传）+ 邀请链接。
- **语音识别依赖浏览器**（Chrome / Edge 的 Web Speech API）。不支持时可在会议页手动补录。
- **WebRTC 在无公网 STUN/TURN 的内网环境下可能无法穿透**，会议页会降级为文字转写 + 纪要模式；
  跨网络部署建议配置自有 TURN 服务。
- **支付为演示实现**，接真实支付需替换 `payments` 相关逻辑。
- 端口占用时 `node server.js --port 9000` 换端口即可。
