# 短剧 × 短视频：外接短剧上传 + 平台分发（方案 v2）

> 修正：短剧**不由平台生成**，而是**外接短剧内容、上传到平台**，平台做
> 「上架 → 审核 → 分发 → 切片引流 → 数据 → 商业化」。
> 短视频仍由平台自动生成（每条信息一条片），负责把观众送到项目和短剧。

---

## 一、角色分工

| 角色 | 做什么 |
|---|---|
| **短剧版权方 / 内容方**（外部） | 提供剧集文件、封面、简介、授权书 |
| **平台运营**（你/管理员） | 上传剧集、审核上架、排推荐位、看数据 |
| **观众**（C 端） | 刷短视频、看短剧、追剧、点信息卡进项目 |
| **项目方** | 提供真实项目信息（平台生成短视频） |

---

## 二、产品形态：短剧怎么进平台

### 1. 短剧频道（#/drama）

```
推荐位（轮播 3 部）
分类：都市 / 商战 / 创业 / 逆袭 / 情感 / 悬疑 / 产业（按平台用户口味）
剧集卡片：封面 + 剧名 + 集数 + 更新状态 + 追剧按钮
我的追剧
```

### 2. 剧集播放页（#/drama/:seriesId/:ep）

```
竖屏播放器（复用现有短视频播放器）
选集（1~N 集）、上下集、自动连播
追剧 / 分享
广告位：片头 5 秒贴片（可跳过）、暂停贴片
第 1 集免费，后续集可设「看广告解锁」或会员（待支付能力）
```

### 3. 短视频流导流（关键结合点）

```
外部短剧上传后，平台自动做切片：
  · 每集自动截 3~5 个 15 秒高光片段（ffmpeg 切片）
  · 作为短视频投放到 #/shorts 信息流（标「短剧」标签）
  · 用户刷到 → 点进剧集 → 追剧 / 点信息卡进项目
```

**这就是「短视频 × 短剧」的结合方式：**
```
短视频流 = 流量入口（平台自产信息片 + 短剧切片）
短剧     = 留人内容（外部供给，平台分发）
信息卡   = 转化出口（真实项目 → 企业服务成交）
```

### 4. 项目详情页联动

```
项目详情页底部：「相关短剧推荐」/「看商战短剧，学项目怎么谈」
短剧播完 → 推荐同行业真实项目 → 回到平台成交
```

## 三、数据模型（新增，不破坏现有 feeds）

```js
// dramas.json —— 短剧（一部剧）
{
  id: 'dr_xxx',
  title: '算力争夺战',
  subtitle: '商战 · 6 集',
  category: 'business',        // 都市/商战/创业/逆袭/情感/悬疑/产业
  intro: '……',
  coverUrl: '/files/...',
  provider: '版权方名称',       // 外部内容方
  licenseNote: '已获授权，授权书见附件',
  licenseFileId: 'f_xxx',
  totalEpisodes: 6,
  status: 'draft|pending|published|rejected|offline',
  featured: false,              // 首页推荐
  freeEpisodes: 1,              // 前几集免费
  views: 0, follows: 0, likes: 0,
  createdAt: '...', publishedAt: '...'
}

// dramaEpisodes.json —— 剧集（一集）
{
  id: 'de_xxx',
  dramaId: 'dr_xxx',
  episodeNo: 3,
  title: '第 3 集：谁拿下了那 2000 个机柜',
  fileId: 'f_video_id',         // 上传的视频文件
  durationSec: 95,
  coverUrl: '',
  clips: [                      // 自动切片生成的短视频 feed id
    { feedId: 'fd_xxx', startSec: 12, endSec: 27 }

}
```

```js

```

## 四、上传与审核流程（MVP）

### 上传（运营后台 or 版权方账号）

```
#/admin-drama/upload
  1. 填剧名、简介、分类、总集数、免费集数
  2. 上传封面（或自动截帧）
  3. 批量上传剧集视频（按文件名排序，自动识别集数）
  4. 填版权方名称 + 上传授权书（必填）
  5. 勾选版权承诺
  6. 提交 → 状态 pending
```

### 审核（管理员）

```
#/admin-drama
  · 待审核列表：预览播放、看封面/简介/授权书
  · 通过 → published（进入频道 + 生成切片投放短视频流）
  · 驳回 → rejected（填原因）
  · 已上架：下架、改推荐位、改免费集数、看数据
```

### 自动处理（服务器 ffmpeg）

```
· 上传视频自动转码为 720×1280（h264 + aac，faststart）
· 自动截 3 张封面候选
· 每集切 3 个 15 秒高光片段 → 生成短视频 feed（带「短剧」标签）
· 自动生成剧集标题（从文件名/简介）
```

## 五、商业化（外接模式）

| 收入 | 方式 | 说明 |
|---|---|---|
| 贴片广告 | 片头 5 秒 / 暂停贴片 | CPM 30~80 元，需广告主或联盟 |
| 解锁/会员 | 第 1 集免费，后续看广告解锁或会员 | 会员需支付能力（备案后） |
| 平台采买转售 | 低价采买短剧，靠广告/会员回收 | 需版权谈判能力 |
| 分账合作 | 版权方供内容，平台出流量，广告收入分成 | 常见做法：5:5 或 6:4 |
| 导流成交（核心） | 短剧 → 项目信息卡 → 企业服务成交 | 走现有 9 条收入线 |
| 定制短剧 | 园区/政府/品牌定制 | 5 万~30 万/季 |

**MVP 阶段先不做支付**：只做「贴片广告位 + 信息卡导流 + 数据看板」，避免卡在备案。

## 六、合规红线（外接内容必须做）

```
① 版权：每部剧必须上传授权书 + 版权承诺；无授权不上架
② 内容审核：人工过一遍（涉黄涉暴涉政、虚假宣传、诱导付费）
③ 微短剧备案：按主管部门要求，平台需核验内容备案信息（有则填编号）
④ 付费/广告：不得诱导未成年人付费；广告需标注「广告」
⑤ 投诉通道：侵权/违规一键举报，24 小时内下架
```

## 七、实施路径

### 第一步：能上传、能看、能审核（1~2 周）

```
· dramas / dramaEpisodes 数据模型 + API
· 后台上传页（剧名/分类/批量剧集/封面/授权书）
· 审核页（通过/驳回/下架）
· #/drama 频道页 + #/drama/:id/:ep 播放页（选集、连播、追剧）
· 短视频流插入「短剧切片」（先手动上传切片，后续自动切）
```

### 第二步：自动切片 + 数据（1 周）

```
· 上传后自动转码、截封面、切 15 秒高光片段
· 数据看板：播放量、完播率、追剧数、跳转项目数
· 推荐位管理
```

### 第三步：商业化（备案后）

```
· 贴片广告位接入
· 看广告解锁 / 会员
· 版权方分账后台
```

## 九、已实现：短视频 / 短剧「分开发布」（2026-11-07 调整）

> 先做过「短视频 + 短剧一次发布」，用户反馈要求**分开**，已改回两个独立入口。

```
入口一：发布短视频    #/publish?category=short
   原有的短视频上传流程，未做改动

入口二：发布短剧      #/publish-drama（发布板块里的「🎬 短剧」卡片）
   1) 填剧名 / 分类 / 副标题 / 免费集数 / 剧情简介 / 内容方 / 授权说明
   2) 批量选择剧集视频（多选，按顺序成为第 1~N 集）
   3) 点「上传并发布」：
        · 逐个上传视频（显示进度）
        · 一次创建短剧 + 全部剧集
        · 自动上架短剧频道
        · 自动切 15 秒高光片段投放到短视频流
        · 跳转 #/drama/:id
   · 权限：目前仅平台运营（管理员）；普通用户看到「版权方合作」说明与联系入口
   · 旧链接 #/publish?category=drama 自动跳转到 #/publish-drama

短剧管理：#/admin-drama（审核、下架、补切片、删除）
```

技术：
- `POST /api/admin/dramas/from-videos`：一次创建剧 + 集 + 上架 + 切片（发布短剧页复用）
- 前端 `views-publish-drama.js`：独立发布页；`views-publish.js` 恢复原短视频流程并增加短剧入口卡
