# 1 引言

## 1.1 编写目的

这份说明书是给两类人看的：

- 平台用户——想知道每个功能怎么用、点哪里；
- 平台运维和技术人员——想知道系统怎么部署、出了问题怎么查。

写这份文档的时候，我把开发过程中实际踩过的坑也一并写进去了。有些地方看起来像是"不该写进说明书"的细节，但正是这些细节决定了系统能不能稳定跑起来。建议运维同学至少把第 15 章看完。

## 1.2 软件概述

小鱼来了是一个产业信息发布与对接平台，简单说就是"找项目、投资、产业"的地方。

谁在用：

- 地方政府招商部门和产业园区——发布招商需求，找能落地的企业；
- 国资、城投平台——发布项目招标和合作需求；
- 投资机构——找可投的项目；
- 本地规模企业——发布采购、供应、融资、技术攻关需求；
- 服务商——承接上面这些需求。

平台干的事就三件：

1. **把信息标准化**。用户随便贴一段文字、传一张图片或者一个 PDF，系统用 AI 把行业、地区、金额、阶段这些要素抽出来，变成结构化数据。不然一堆自由文本没法检索也没法匹配。
2. **把信息推给对的人**。按行业和城市做匹配，只推给可能感兴趣的人。这里我们踩过一个大坑，后面第 15 章会细讲——一开始是全量推送，结果通知表三个月涨到 268MB，把服务器内存撑爆了。
3. **把对接过程留痕**。谁看了、谁联系了、联系到哪一步，都能查。

# 2 运行环境

## 2.1 服务器端

服务器端是**零依赖**的。所谓零依赖，就是 `npm install` 一个包都不用装——整个服务只用 Node.js 内置模块写。

这么做有两个原因：一是这个项目是我一个人维护，依赖越少升级越不容易出问题；二是服务器内存只有 2G，装一堆包光 node_modules 就占几百兆不划算。

| 项 | 要求 | 实际部署 |
|---|---|---|
| 操作系统 | Linux（推荐 Ubuntu 20.04 及以上） | Ubuntu 22.04 LTS |
| Node.js | 18.0 及以上 | v20.20.2 |
| 内存 | 最低 1GB，推荐 2GB | 2GB |
| 磁盘 | 最低 20GB | 50GB SSD |
| CPU | 1 核起 | 2 核 |
| 反向代理 | nginx（推荐） | nginx 1.18.0 |
| 证书 | Let's Encrypt 免费证书 | certbot 1.21.0 |

**说明**：2GB 内存是因为 Node 进程常驻要占 100~200MB，加上 nginx 和系统，留出余量。如果内存只有 1GB，跑得起来但一旦有大数据量导出容易 OOM。

## 2.2 客户端

| 项 | 要求 |
|---|---|
| 浏览器 | Chrome 80+、Safari 14+、Edge 80+、微信内置浏览器 |
| 移动端 | iOS 14+、Android 10+ |
| 分辨率 | 最小 320px 宽，适配到 2560px |
| 网络 | 能访问外网即可，无需装任何插件 |

## 2.3 第三方服务（可选）

平台上有些功能依赖第三方服务，不配也能跑，只是对应功能不可用。

| 服务 | 用途 | 不配的影响 |
|---|---|---|
| DeepSeek API | AI 生成标题、解析正文 | AI 辅助功能不可用，需手动填写 |
| SiliconFlow API | 图片识别、语音转文字 | 图片和视频内容无法自动识别 |
| 微信公众平台 | 微信登录、模板消息 | 只能用手机号/邮箱登录 |
| SMTP 邮箱 | 邮件通知 | 只发站内通知 |
| 高德地图 | 地址解析 | 地址需手动填写 |

API Key 都放在服务器 `/opt/xiaoyu-laile/.env` 文件里，不写进代码，也不进代码仓库。

# 3 安装与部署

## 3.1 部署包结构

```
xiaoyu-laile/
├── server.js              服务入口
├── package.json           项目描述（无第三方依赖）
├── .env                   环境配置（API Key 等，不进仓库）
├── src/
│   ├── config.js          配置加载
│   ├── http/              自研 HTTP 框架
│   ├── store/             数据存储层
│   ├── routes/            路由（20 个模块）
│   ├── services/          业务逻辑（45 个模块）
│   ├── lib/               工具库
│   └── data/              静态数据（行业、城市、分类）
├── public/                前端资源
│   ├── index.html
│   ├── static/            前端脚本与样式
│   └── sw.js              Service Worker
├── scripts/               运维脚本
└── data/                  运行时数据（自动生成）
    ├── collections/       数据表（JSON 文件）
    ├── uploads/           上传的文件
    └── .secret            密钥文件
```

## 3.2 部署步骤

### 步骤 1：安装 Node.js

用 NodeSource 的源装 Node 20：

```bash
curl -fsSL https://deb.nodesource.com/setup_20.x | bash -
apt-get install -y nodejs
node -v
```

看到 `v20.x.x` 就对了。

### 步骤 2：上传程序

把程序包解压到 `/opt/xiaoyu-laile`：

```bash
mkdir -p /opt/xiaoyu-laile
tar -xzf xiaoyu-laile.tar.gz -C /opt/xiaoyu-laile
cd /opt/xiaoyu-laile
```

### 步骤 3：配置环境变量

复制 `.env.example` 为 `.env`，填入实际配置：

```bash
cp .env.example .env
vim .env
```

至少要配这几项：

```bash
APP_NAME=小鱼来了
PUBLIC_BASE_URL=https://你的域名
AI_API_KEY=你的 DeepSeek Key
VISION_API_KEY=你的 SiliconFlow Key
```

### 步骤 4：配置 systemd 守护

新建 `/etc/systemd/system/xiaoyu-laile.service`：

```ini
[Unit]
Description=Xiaoyu Laile Platform
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/xiaoyu-laile
ExecStart=/usr/bin/node server.js --port 8787
Restart=always
RestartSec=3
User=root

[Install]
WantedBy=multi-user.target
```

启动并设为开机自启：

```bash
systemctl daemon-reload
systemctl enable xiaoyu-laile
systemctl start xiaoyu-laile
systemctl status xiaoyu-laile
```

### 步骤 5：配置 nginx

新建 `/etc/nginx/sites-available/xiaoyu-laile`：

```nginx
server {
    listen 80;
    server_name 你的域名;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name 你的域名;

    ssl_certificate     /etc/letsencrypt/live/你的域名/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/你的域名/privkey.pem;

    client_max_body_size 500m;

    gzip on;
    gzip_comp_level 6;
    gzip_min_length 512;
    gzip_types text/plain text/css text/javascript
               application/javascript application/json
               application/xml image/svg+xml;

    location / {
        proxy_pass http://127.0.0.1:8787;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # 长连接与上传需要
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
        proxy_buffering off;
    }
}
```

启用并重载：

```bash
ln -s /etc/nginx/sites-available/xiaoyu-laile /etc/nginx/sites-enabled/
nginx -t
systemctl reload nginx
```

**注意 gzip 这一段一定要写全**。我们一开始漏了 `gzip_types`，nginx 就只压缩 HTML，JS 和 CSS 全是裸传，首屏 790KB 原样发出去。这个问题第 15 章会细讲。

### 步骤 6：申请证书

```bash
apt-get install -y certbot python3-certbot-nginx
certbot --nginx -d 你的域名
```

### 步骤 7：验证

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8787/api/health
curl -s -o /dev/null -w "%{http_code}\n" https://你的域名/
```

两个都返回 200 就部署成功了。

# 4 用户注册与登录

## 4.1 注册方式

平台支持三种注册方式，入口都在首页右上角「登录 / 注册」。

【图 4-1：登录注册页面】

### 4.1.1 手机号注册

1. 点「注册」标签；
2. 输入 11 位手机号；
3. 点「获取验证码」，等待短信；
4. 填入 6 位验证码；
5. 设置密码（至少 6 位）；
6. 勾选用户协议；
7. 点「注册」。

注册成功后自动登录，并跳转到刚才想去的页面。

**关于图形验证码**：注册和登录都要过一次图形验证码。这个不是多余——之前没有验证码的时候，短信接口被人刷过，一小时发了几百条。现在每次发短信前必须先通过图形验证码。

【图 4-2：图形验证码】

### 4.1.2 邮箱注册

和手机号注册基本一样，只是把手机号换成邮箱地址，验证码发到邮箱里。

**提示**：如果邮件迟迟收不到，先看垃圾邮件箱。用企业邮箱的话，有时候会被拦。

### 4.1.3 微信登录

在微信里打开网站，点「微信登录」，走公众号授权。

这个功能需要先在后台配置微信公众号的 AppID 和 AppSecret。没配置的情况下会走"演示模式"，能登录但不是真实的微信账号。

## 4.2 登录

1. 点右上角「登录 / 注册」；
2. 输入手机号（或邮箱）+ 密码；
3. 点「登录」。

**保持登录**：登录状态保存在浏览器 localStorage 里，默认 30 天有效。换浏览器或清理缓存后需要重新登录。

## 4.3 忘记密码

点登录页的「忘记密码」：

1. 输入注册时的手机号；
2. 获取验证码；
3. 设置新密码。

**注意**：如果手机号已经不用了，支持提交人工申诉，走「联系我们」里的渠道，需要提供企业营业执照或身份证明。

## 4.4 实名认证

发布信息前需要完成实名认证。

个人认证：上传身份证正反面。
企业认证：上传营业执照，填写统一社会信用代码。

提交后由管理员审核，一般 1 个工作日内完成。审核通过后发布信息不再受限。

# 5 信息发布

## 5.1 发布入口

首页中间有个蓝色的「发布信息」横栏，点「去发布」进入发布页。底部导航中间的「＋」也能进。

【图 5-1：发布入口】

## 5.2 选择发布板块

发布页第一步是选板块。目前有这些：

| 板块 | 适用内容 |
|---|---|
| 项目 | 投资、融资、EPC、招标、合作 |
| 活动赛事 | 展会、沙龙、论坛、赛事、课程、饭局、团建 |
| 贸易采供 | 采购、供应、租赁、委托加工 |
| 科技成果转化 | 专利、技术转让、产学研、作价入股 |
| 创业补贴 | 创业补贴、场地、人才、研发补贴 |
| 辅导 | 商业模式、融资、申报、市场辅导 |
| 悬赏 | 技术、方案、资源、人才悬赏 |
| 招投标 | 招标公告、中标结果、变更公告 |
| 短视频 | 项目实拍、企业宣传 |
| 直播 | 项目路演、招商推介 |

选完板块，下面的表单会自动变化——比如选"活动赛事"会多出报名时间、活动地点；选"贸易采供"会多出数量和价格。

## 5.3 AI 辅助填写

这是平台最核心的功能，也是我们花时间最多的部分。

### 5.3.1 三种输入方式

**方式一：直接打字**

在正文框里输入你想发布的内容。写得粗糙没关系，系统会整理。

**方式二：上传文件**

支持上传：

- 图片（JPG / PNG / WebP / BMP）
- 文档（PDF / Word / PPT / Excel / TXT / Markdown）
- 压缩包（ZIP / RAR / 7Z）

把文件拖到上传区，或者点「选择文件」。

**关于图片识别**：只传图片不写字的情况很常见——用户拍了张招标公告的照片就想发出去。系统会把图片送去做 OCR 识别，把文字提出来。这个功能依赖 SiliconFlow 的视觉模型，识别速度跟图片大小有关，一张 A4 大小的图和一张手机截图大概都在 1~3 秒。

**方式三：粘贴链接**

在「从链接导入」里粘贴一个网页地址，系统会：

1. 抓取网页正文；
2. 去掉广告、联系方式、二维码这些无关内容；
3. 提取标题和正文。

这个功能对转载政策文件、招标公告特别有用——直接复制政府网站的链接就行。

### 5.3.2 AI 生成主标题和副标题

点击「AI 智能生成」按钮，系统会基于你填的内容生成：

- **主标题**：一句话概括这条信息是什么，控制在 30 字以内；
- **副标题**：补充关键要素（金额、地点、规模、时间等）。

生成后可以自己改。不满意就再点一次，每次生成的结果会有点不一样。

**实际效果举例**：

输入这段：

> 我们公司在东营有个 200MW 的渔光互补光伏电站项目，要找 EPC 总承包，预算 2.8 个亿，工期 18 个月，需要电力工程施工总承包二级以上资质

生成的主标题：

> 山东东营 200MW 渔光互补光伏电站 EPC 总承包招标

副标题：

> 预算 2.8 亿元 · 工期 18 个月 · 需电力施工总承包二级以上

### 5.3.3 联系方式自动脱敏

这一点很多人第一次用会觉得奇怪，但确实是有意设计的。

平台会检测正文里的手机号、邮箱、微信号、QQ 号、固定电话，把它们**替换成星号**：

```
输入：有意的联系 138 0000 1234
输出：有意的联系 138 **** 1234
```

**为什么要这么做**：

1. 平台是按条信息和行业匹配的，公开显示完整联系方式，等于把用户线索白送出去，以后就没人愿意在平台发了；
2. 工信部对平台的个人信息保护有要求，公开展示手机号有合规风险。

**联系方式怎么给**：注册用户登录后，在详情页点「查看联系方式」，会显示完整号码。未登录用户只能看到脱敏后的。

### 5.3.4 多项目自动拆分

如果一条正文里写了多个不相关的项目，系统会问你要不要拆成多条分别发布。

比如这段话：

> 我们这边有三个项目：一个是东营 200MW 光伏，一个是乌兰察布 500MW 风电，还有一个是常州 100MWh 储能

系统会识别出三个项目，问你是否分别发布。确认后就变成三条独立的信息，各自可以匹配到不同的行业和地区。

**贸易类不拆分**——因为贸易发布经常是"一批货里有好几种物资"，拆开反而没法看。这类会汇总成一张表格。

## 5.4 补充要素

AI 生成完标题后，下面还有一些需要手动补充的：

| 字段 | 是否必填 | 说明 |
|---|---|---|
| 所属行业 | 必填 | 最多选 3 个，影响匹配 |
| 所在城市 | 必填 | 精确到区县，影响匹配 |
| 有效期 | 默认 90 天 | 到期自动下架 |
| 封面图 | 选填 | 不传会自动从图片里截取 |
| 附件 | 选填 | 补充材料 |

## 5.5 发布与审核

点「发布」后：

1. 系统先做一次自动检查（敏感词、联系方式、重复内容）；
2. 检查通过直接上线；
3. 有疑问的进入人工审核队列。

**审核规则**：

- 同一条内容重复发布 → 提示"已存在相似内容"；
- 含明显广告、赌博、色情 → 直接拒绝；
- 含未脱敏的联系方式 → 自动脱敏后放行；
- 其他 → 人工审核。

## 5.6 短视频批量发布

短视频支持**一次最多发 3 条**。

【图 5-2：短视频发布页】

操作：

1. 选板块「短视频」；
2. 点「选择视频（最多 3 条）」；
3. 一次可以选多个，也可以一个一个加；
4. 系统会逐条解析时长、分辨率，并自动截取 3 帧画面给 AI 识别内容；
5. 填标题（第 1 条用你填的，其余由 AI 生成）；
6. 点发布。

**关于视频大小**：建议单条 200MB 以内。30~100MB 的视频会先在浏览器里压缩再上传，更大的会传完后在服务器压缩成 720p。

**手机上选不了多个是正常的**——微信内置浏览器和 iOS Safari 会忽略多选属性。这种情况下点一次选一个，再点一次继续加，最多 3 次。

## 8.2 更新频率

- 服务启动 90 秒后抓一轮；
- 之后每 3 小时抓一次。

## 8.3 行业标签

每篇资讯会被自动打上行业标签：光伏、储能、风电、算力、AI、机器人、无人机、飞行汽车、氢能、投融资、政策。

标签是按关键词规则打的，不是人工标注。

**这里有个已知问题**：「政策」标签的规则里有"标准""方案""意见""办法"这类泛词，手机评测、AI 新闻也会命中，导致"政策"标签下有很多非政策内容。我们在页面上做了二次判断——只有来源是发改委、能源局、工信部这些政府网站的，标题才加「政策｜」前缀。

## 8.4 每日摘要

平台每天会把新抓到的资讯合成一条摘要推给用户，而不是每篇都推。

摘要长这样：

```
📰 今日行业资讯 12 条，关于进一步完善价格形成机制 等

1. 关于进一步完善价格形成机制 推动普惠养老服务提质扩面的指导意见
2. 关于印发浙江高质量发展建设共同富裕示范区经验做法(第三批)的通知
...

点击查看全部资讯
```

**为什么不是每篇推**：以前是每篇推一次，一条资讯 × 300 多个用户，一天几千条通知，三个月后通知表 268MB，服务被 OOM 杀掉 32 次。改成每日摘要后，通知量降到原来的 3% 左右。

# 完整备份

```

## 14.3 备份到本机

为了防止服务器整机故障导致备份一起丢，建议定期把备份拉到本地电脑：

```

## 14.4 恢复

```bash
systemctl stop xiaoyu-laile
cd /opt/xiaoyu-laile
tar -xzf backups/daily/xyll-db-20261125-0300.tar.gz
systemctl start xiaoyu-laile
```

**注意**：恢复前先把当前数据表备份一份，不然恢复错了就找不回来了。

## 14.5 一个必须知道的坑

**修改数据表文件必须先停服务。**

原因是程序启动时会把所有数据表读进内存，运行期间改的是内存里的副本，退出时才写回磁盘。如果你直接编辑 `data/collections/*.json`，然后重启服务——内存里的旧数据会把你的修改覆盖掉。

正确做法：

```bash
systemctl stop xiaoyu-laile     # 先停
vim data/collections/xxx.json   # 再改
systemctl start xiaoyu-laile    # 后启
```

# 15 系统运维与故障处理

这一章记录的是实际遇到过的问题。有些问题当时排查了很久，写下来供以后参考。

## 15.1 通知表膨胀导致服务反复重启

**现象**：用户反馈"系统反应慢，有时候打不开"。查负载发现很低（load 0.00），但服务会不定时重启。

**排查过程**：

1. 先看内存：Node 进程 RSS 462MB，服务器总共 2GB；
2. 看数据文件：`notifications.json` 268MB；
3. 数记录：506,940 条通知；
4. 查系统日志：`journalctl -u xiaoyu-laile | grep -i oom` 发现 7 天里 408 行 OOM 记录，服务重启 32 次。

**根因**：

- 每条新闻 × 331 个用户全量推送，30 天累计 269,337 条；
- 每个新项目 × 全体会员，30 天累计 235,130 条；
- 通知表**完全没有清理策略**，只增不减。

**处理**：

1. 凌晨低峰期停服务，把通知按"最近 30 天 + 每人最多 200 条"裁剪，268MB → 33MB；
2. 重启后 Node 内存从 462MB 降到 80MB；
3. 代码层加自动清理任务，每 6 小时跑一次；
4. 新闻改成每日摘要推送；
5. 新项目改成按兴趣推送。

**现在的状态**：通知量从每月约 50 万条降到约 1.3 万条，内存稳定在 100~200MB。

## 15.2 首屏加载慢

**现象**：用户反馈打开慢。

**排查**：

1. 服务器本地测 API，全部 1~5ms，不是后端慢；
2. 测 nginx，加 TLS 也只要 13ms；
3. 检查 nginx 配置，发现 `gzip_types` 整行被注释了。

**根因**：nginx 的 gzip 默认只压缩 `text/html`，JS、CSS、JSON 全部裸传。

实测：

```
views-home.js     112,805 字节 → 经 nginx 还是 112,805 字节
```

首屏 JS+CSS 合计 790KB，一点没压。

**处理**：

```nginx
gzip_types text/plain text/css text/javascript
           application/javascript application/json
           application/xml image/svg+xml;
gzip_comp_level 6;
gzip_min_length 512;
```

效果：

```
views-home.js  112,805 → 29,949  （省 73%）
home.css        45,412 →  9,793  （省 78%）
首屏合计        790 KB → 210 KB  （省 73%）
```

同时把 `listen 443 ssl` 改成 `listen 443 ssl http2`，首屏 27 个请求从排队变成并发。

## 15.3 发布短视频报错 `autoCover is not defined`

**现象**：用户点发布短视频，页面报错，视频发不出去。

**根因**：变量 `autoCover` 声明在 `if (!isLive) { ... }` 这个块里，但提交处理函数在块外面用到了它。

```javascript
if (!isLive) {
  let autoCover = null;   // ← 只在块内有效
}
// 提交时
submitBtn.onclick = () => {
  upload(autoCover);      // ← ReferenceError
}
```

**处理**：把 `let autoCover = null;` 提到外层作用域。

这个 bug 是单元测试没覆盖到的地方——发布流程涉及浏览器 API（MediaRecorder、Canvas），不好写测试。后来补了一个用 Canvas 生成 1 秒假视频、走完整发布流程的端到端测试。

## 15.4 群二维码扫码提示"您不在该群聊中"

**现象**：把群二维码发给别人，别人扫码后看到的是一整个报错页。

**根因**：

1. 二维码的 URL 是 `#/chat/群ID`；
2. 后端对非成员的请求返回 403；
3. 前端没有处理 403，直接进了全局错误页。

**处理**：

1. 后端加 `GET /api/chat/rooms/:id/preview` 接口，非成员也能拿到群名、成员数、简介；
2. 前端捕获 `not_member` 错误码，渲染"加入群聊"引导页；
3. 群设了密码的，引导页显示密码输入框。

## 15.5 微信转发卡片显示通用标题

**现象**：把信息转发到微信，卡片标题永远是"小鱼来了 · AI 信息发布平台"，不是具体内容。

**根因**：前端路由用的是 hash 模式（`/#/detail/xxx`），而微信抓取链接时**只抓 # 前面的部分**，`#` 后面的内容不会发到服务器。所以服务器永远只能返回 `index.html` 里那个通用标题。

**处理**：改成路径式短链：

```
/#/detail/xxx  →  /s/xxx
```

服务端拿到 id 后，把 `index.html` 里的 title、description、og:* 标签动态替换成这条信息的真实内容，再返回。

同时前端打开页面后不跳转地址（保留 `/s/xxx` 路径），只在渲染时补上 hash 路由。

## 15.6 微信里打开要"继续访问"两次

**现象**：微信里点链接，会先出现一个"继续访问"的提示，点完才进去。

**原因**：这是微信对**未备案境外服务器**的安全拦截。服务器在香港，域名没有 ICP 备案号，微信和部分国产浏览器会拦。

**处理**：根治只能做 ICP 备案，把服务器迁到大陆。这是网站合规问题，不是技术问题。

## 15.7 备份 20 天没成功过

**现象**：查日志发现备份从某天起一直失败。

**根因**：`backup.sh` 在执行某次部署后丢了可执行权限（从 755 变成 644），cron 执行时报 `Permission denied`。

**处理**：

1. `chmod 755 backup.sh`；
2. cron 从直接执行改成 `/bin/bash backup.sh` 显式调用，这样即使丢权限也能跑。

## 15.8 日常巡检清单

建议每周看一次：

```bash
# 1. 服务状态
systemctl is-active xiaoyu-laile

# 2. 内存占用（超过 400MB 要警惕）
ps aux | grep "node server.js" | grep -v grep | awk '{print $6/1024 " MB"}'

# 3. 数据目录大小（异常增长要查）
du -sh /opt/xiaoyu-laile/data/*

# 4. 最近有没有 OOM
journalctl -u xiaoyu-laile --since "7 days ago" | grep -ci oom

# 5. 备份是否正常
tail -20 /var/log/xyll-backup.log

# 6. 磁盘空间
df -h /
```

# 16 常见问题

**Q：注册收不到短信验证码？**

A：先确认手机号没填错。然后看是不是图形验证码没填。如果都正常，可能是短信通道临时拥堵，等 1 分钟重试。

**Q：发布信息提示"存在相似内容"？**

A：系统会比对标题相似度，超过阈值的算重复。如果确实是不同的信息，把标题改得具体一点再试。

**Q：为什么联系人是星号？**

A：平台对所有公开发布的联系方式做了脱敏处理，登录后点"查看联系方式"能看到完整号码。

**Q：为什么收不到新项目通知？**

A：检查两件事：一是个人中心的"通知偏好"里"平台有新项目上线时通知我"有没有关闭；二是"我关注的行业与地区"有没有设置。没设置兴趣的用户只会收到每周摘要。

**Q：短视频上传很慢？**

A：视频文件大就会慢。建议单条 200MB 以内，或者在微信里先把视频发给自己（微信会自动压缩），再保存上传。

**Q：手机上为什么只能选一个视频？**

A：微信内置浏览器和 iOS Safari 不支持文件多选。点一次选一个，连点 3 次就能加满 3 条。

**Q：AI 生成的标题不满意？**

A：点「AI 智能生成」再点一次，每次结果不同。也可以手动改。

**Q：信息到期了怎么办？**

A：在「我的发布」里找到那条信息，点「续期」。续期后重新计算有效期。

**Q：怎么查看我邀请了多少人？**

A：「我的」→「推荐有礼」，页面上显示已邀请人数和名单。

**Q：能导出发布的信息吗？**

A：目前不支持导出。如果确实需要，联系管理员。
