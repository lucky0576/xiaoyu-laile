## 选题说明：为什么是第 5 项

七个课题里，小鱼来了真正有**一手场景和数据**的是第 5 项，理由有三条：

**① 平台本身就是一个闭环的反馈系统**

小鱼来了的业务链路天然产生「策略 → 曝光 → 用户行为 → 结果」的完整日志：

```
内容发布 → AI 解析（行业/区域/金额/阶段）→ 匹配策略 → 推送/排序 → 用户行为 → 对接结果
                ↑                                                          │
                └──────────────── 反馈回流，策略更新 ←──────────────────────┘
```

这不是为了做研究临时搭的实验环境，而是**本来就在跑的业务流程**。

**② B2B 场景的反馈特性，正是当前在线 RL 研究最薄弱的环节**

阿里体系内做在线 RL 的场景（淘宝推荐、饿了么派单、飞猪定价）都是 **C 端高频、即时、稠密反馈**。而 B2B 产业撮合有三个完全不同的性质：

| 维度 | C 端典型场景 | B2B 产业撮合（本项目） |
|---|---|---|
| 反馈密度 | 毫秒~秒级点击 | 天~周级的电话、留言、线下对接 |
| 奖励性质 | 即时、可归因 | **延迟、稀疏、多跳归因** |
| 曝光偏差 | 强，但有海量样本校正 | 更强（样本少），且中小发布方极易被淹没 |
| 分布漂移 | 缓慢 | **剧烈**（产业热点切换：光伏→储能→算力→机器人） |

**「样本少 + 延迟长 + 偏置强 + 漂移快」** 这四个约束叠加，是一个真实存在、且在公开文献中尚未被充分解决的在线 RL 问题。

**③ 成果能直接回到阿里生态**

产业供需匹配、招商线索、企业服务撮合，是阿里云、钉钉、1688、瓴羊都在做的方向。本课题产出的「稀疏延迟反馈下的在线学习 + 反事实评估」方法，可以直接迁移到 B 端产品的推荐与撮合场景。

**备选课题**：第 6 项《面向复杂视觉场景的 Agentic Search 强化学习训练系统》。
平台已建成垂直语料库（1400+ 资讯、925+ 招投标公告、1200+ 供需信息）与 AI 检索入口，也具备条件。但「复杂视觉场景」与平台现有内容形态（封面图、短视频）贴合度不如第 5 项的反馈闭环紧密，故列为备选。

## 一、项目背景及研究意义

### 1.1 产业背景

中国产业招商与供需对接长期存在严重的**信息不对称**：政府园区找不到匹配的企业，中小企业找不到对口的需求方，投资机构找不到可落地的项目。传统解法是线下推介会、中介撮合、行业微信群，效率低、不可规模化、过程不可留痕。

2024 年以来，大模型让「内容理解 + 语义匹配」的成本大幅下降，产业信息平台开始具备规模化撮合的可能。但**「理解内容」只解决了一半问题**——真正决定平台价值的是**「把哪条信息推给哪个人、什么时机推、推多少次」**，这是一个典型的序列决策问题，本质上属于强化学习范畴。

### 1.2 技术背景

在线强化学习在推荐与排序已相当成熟（如 YouTube 的 REINFORCE 推荐、淘宝的在线 bandit 排序），但这些方法建立在三个前提上：反馈稠密、延迟短、样本充足。

B2B 产业撮合场景同时打破了这三个前提：

- **反馈稀疏**：一条供需信息可能只被浏览几十次，真正的「有效对接」可能只有个位数；
- **奖励延迟**：从推送、点击、电话沟通到最终签约，周期可达数周甚至数月；
- **选择偏置**：平台的推送策略决定了用户能看到什么，直接拿日志训练会不断放大既有策略（feedback loop / filter bubble），中小发布方被系统性忽略；
- **分布漂移**：产业热点按季度甚至按月切换，上一季度学到的最优策略下季度可能失效。

现有方法（延迟反馈建模 DFM、逆倾向加权 IPS、保守 Q 学习 CQL）各自只解决其中一两个问题，**缺少一个同时处理「稀疏 + 延迟 + 偏置 + 漂移」的统一框架**。

### 1.3 研究意义

**科学意义**

1. 提出面向**低样本、长延迟、强偏置**场景的在线强化学习框架，填补现有方法在 B2B 撮合场景的空白；
2. 建立「弱信号 → 长期价值」的奖励建模方法，把点击、停留、收藏等即时弱信号与电话、留言、成交等延迟强信号统一到一个奖励函数中；
3. 提出可落地的**反事实评估方法**，在无法大规模 A/B 的条件下估计策略收益。

**产业意义**

1. 直接提升产业信息平台的撮合效率，降低中小企业获取商机的成本；
2. 为政府招商部门提供「线索优先级排序」能力，把有限的人力投到最可能落地的项目上；
3. 形成可复用的方法论与开源工具，服务更广泛的 B 端撮合场景。

**平台基础（已验证的工程与数据底座）**

小鱼来了已完成从内容生产到匹配推送的完整闭环，具备承接本课题的工程条件：

| 维度 | 现状 |
|---|---|
| 内容规模 | 1,198 条已发布供需信息、1,441 条行业资讯、925 条招投标公告 |
| 用户规模 | 331 个注册用户，覆盖政府园区、国资平台、投资机构、规模企业、服务商五类角色 |
| 标签体系 | 43 个行业、499 个城市/区县、9 大内容分类 |
| AI 能力 | 标题与摘要生成、文档/图片 OCR、联系方式脱敏、供需要素抽取、语义检索 |

## 二、研究目标

### 2.1 总体目标

构建一套**面向稀疏延迟反馈的在线强化学习训练系统**，在真实产业撮合场景中完成从「日志采集 → 奖励建模 → 离策略训练 → 安全上线 → 反事实评估」的全链路闭环，并在小鱼来了平台完成规模化验证。

### 2.2 具体目标

**目标 1：建立可复现的 B2B 撮合强化学习数据集与环境**

- 构建带完整曝光日志、反馈信号、内容上下文、用户画像的序列决策数据集；
- 提供离线仿真环境（off-policy evaluation sandbox），支持策略离线评估；
- 数据与工具开源，供学术界复现。

**目标 2：提出稀疏延迟反馈下的奖励建模方法**

- 融合即时弱信号（浏览、停留、收藏、分享）与延迟强信号（电话、留言、线下对接、成交）；
- 用生存分析 / 延迟反馈建模估计「未来 N 天发生有效对接」的概率；
- 相比直接用点击作为奖励，长期价值估计误差降低 ≥ 30%。

**目标 3：提出抗偏置的在线策略优化算法**

- 结合逆倾向加权（IPS）与双重稳健估计（DR）做离策略校正，抑制曝光偏差；
- 引入保守更新与安全探索机制，保证策略更新不导致线上指标回退；
- 在曝光公平性约束下（Gini 系数不恶化）提升整体匹配效率。

**目标 4：建成可上线的在线训练系统**

- 支持天级（非实时）策略迭代，训练到上线全流程自动化；
- 提供策略效果的反事实估计与置信区间，支持小流量灰度；
- 系统在真实流量上稳定运行 ≥ 3 个月。

**目标 5：形成学术与产业双向产出**

- 发表高水平论文 2~3 篇（含 CCF-A / 顶会 1 篇）；
- 开源框架 1 套、数据集 1 份；
- 申请发明专利 2~3 项。

## 三、研究方法

### 3.1 总体技术路线

```
┌─────────────────────────────────────────────────────────────────┐
│ ① 数据层：全链路日志采集与治理                                    │
│    曝光日志 / 行为日志 / 对接结果 / 内容上下文 / 用户画像          │
└──────────────────────────┬──────────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────────┐
│ ② 建模层：奖励建模 + 用户模拟                                     │
│    · 即时弱信号 → 表征                                            │
│    · 延迟强信号 → 生存分析 / 延迟反馈建模（DFM）                   │
│    · LLM 驱动的反事实用户模拟器（补足稀疏样本）                    │
└──────────────────────────┬──────────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────────┐
│ ③ 训练层：抗偏置在线策略优化                                      │
│    · 上下文 bandit 基线（LinUCB / Neural Bandit）                 │
│    · 离线 RL（CQL / IQL）+ IPS/DR 校正                            │
│    · 约束优化：效率目标 + 公平性约束                              │
└──────────────────────────┬──────────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────────┐
│ ④ 评估层：反事实评估 + 灰度验证                                   │
│    · OPE（IPS / DR / 模型辅助）与置信区间                         │
│    · 小流量 A/B，安全护栏（回退阈值）                             │
└──────────────────────────┬──────────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────────┐
│ ⑤ 回流：策略上线 → 新日志 → 迭代                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 3.2 关键方法

**（1）奖励建模：从弱信号到长期价值**

定义分层奖励：

| 层级 | 信号 | 含义 | 延迟 |
|---|---|---|---|
| L0 曝光 | impression | 是否被展示 | 0 |
| L1 即时弱信号 | 点击、停留时长、展开详情 | 兴趣强度 | 秒级 |
| L2 主动信号 | 收藏、关注、分享、复制联系方式 | 明确意向 | 分钟~小时 |
| L3 强信号 | 电话、留言、发起对接 | 意向确认 | 天级 |
| L4 终局信号 | 线下对接完成、成交、签约 | 真实价值 | 周~月级 |

用 **生存分析（Survival Analysis）+ 延迟反馈建模** 估计 `P(未来 T 天内发生 L3/L4 | 当前上下文)`，作为长期奖励的估计量；L1/L2 作为即时辅助奖励用于降低方差（reward shaping）。

**（2）抗偏置：离策略校正**

平台日志由历史策略 π₀ 产生，直接训练会学到 π₀ 的偏置。采用：

- **逆倾向加权（IPS）**：用 π₀ 的曝光概率做重要性加权；
- **双重稳健估计（DR）**：结合奖励模型与重要性权重，降低方差；
- **倾向得分截断与自归一化**，控制权重爆炸。

**（3）稀疏样本补足：LLM 驱动的反事实用户模拟**

真实 B2B 反馈太少，纯靠日志无法训练。引入大模型构造**用户模拟器**：

- 基于真实用户画像（行业、地域、角色、历史行为）生成合成用户；
- 给定内容与上下文，模拟其「是否会点击 / 收藏 / 联系」；
- 用真实反馈校准模拟器分布（domain adaptation），避免模拟与真实偏离。

**（4）在线优化：带约束的策略更新**

- 基线用 **上下文 Bandit**（LinUCB / Neural Bandit），保证工程可落地；
- 进阶用 **离线 RL（CQL / IQL）+ 在线微调**，处理序列决策与长期收益；
- 引入**约束优化**：在曝光公平性（Gini 系数）不恶化的前提下最大化匹配效率；
- 采用**保守更新**（trust region / KL 约束），超出阈值自动回滚。

**（5）评估：反事实 + 灰度**

- 离线：OPE 估计 + 自助法置信区间；
- 线上：小流量 A/B（5% → 20% → 50%），设回退阈值（核心指标下降 > 3% 自动回滚）；
- 长期：跟踪 7 日 / 30 日留存与对接完成率。

### 3.3 可行性

- 平台已有完整埋点与推送记录，数据可直接用于建模；
- 算法侧以开源框架（PyTorch、Dopamine、RecBole）为基础，无需从零实现；
- 场景规模适中，天级迭代即可满足，不依赖实时推理基础设施；
- 团队具备完整的平台工程能力，可快速落地实验结果。

### 5.2 论文

拟投 2~3 篇，其中 CCF-A / 顶会 ≥ 1 篇。

**论文 1（主攻，目标 KDD / WSDM）**

> *Survival-Analysis-Based Reward Modeling for Delayed and Sparse Feedback in B2B Matching*

- **问题**：B2B 撮合的奖励延迟达周~月级，直接以点击为奖励会优化错目标
- **方法**：分层奖励（L0 曝光 → L4 成交）+ 生存分析估计「未来 T 天发生有效对接」概率
- **贡献**：给出延迟奖励的统一建模范式，在真实平台上验证长期价值预测 AUC 提升 ≥ 20%

**论文 2（目标 WWW / NeurIPS）**

> *Debiasing Online Policy Learning under Severe Exposure Bias and Rapid Distribution Drift*

- **问题**：小样本 + 强曝光偏置 + 产业热点快漂移，三者叠加导致策略自我强化
- **方法**：IPS/DR 校正 + 倾向截断 + 漂移检测与自动重训
- **贡献**：提出低样本条件下的抗偏置在线学习框架，给出 OPE 误差上界分析

**论文 3（目标 SIGIR / CIKM）**

> *Fair-Aware Constrained Reinforcement Learning for Industrial Matching Platforms*

- **问题**：一味优化匹配效率会让中小发布方被系统性淹没
- **方法**：把曝光 Gini 系数作为硬约束，构造约束策略优化
- **贡献**：在效率-公平 Pareto 前沿上给出可操作的权衡方法
